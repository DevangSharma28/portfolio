About

I build games. Some of them are ads.

An ad has seconds to earn someone’s attention. A game has to hold it for hours. I work on both, and each one keeps me honest about the other.

Hi, I'm Devang, a game programmer at Funcell Game Pvt Ltd in Ahmedabad. Two years there, internship included, and 55+ playable ads shipped across Android, iOS and WebGL. Hyper-casual, idle, puzzle, simulation, whatever the brief asks for. I work in C# with Unity and TypeScript with Three.js, and pick up Cocos Creator when a project needs all three platforms at once.

Unity is where I go deeper. I've architected two idle tycoons, Idle Bakery Cafe and Juice King Tycoon, with production chains, worker automation, economies and data-driven world expansion, alongside a car chase with AI police and pooled traffic, a first-person survival game with custom water shaders, and a 2D physics puzzle. Ads taught me to make ten seconds count; Unity is where I get to build the systems underneath: state machines, AI, cameras, progression. Both sides demand the same discipline, because a playable has a hard size cap and a low-end phone still has to run it smoothly.

I lean hard on AI-assisted development. Claude Code, Unity CLI and MCP let me drive the editor, prototype, debug and automate repetitive work much faster, so more of my time goes into the parts of a game that need a human: feel, balance and architecture.

Process

How a build comes together

Five steps, every project, always in this order.

01

Concept

Strip the game down to the single mechanic someone can read in under three seconds.

02

Prototype

Grey-box it and make it playable the same day. Fun is decided here, long before the art lands.

03

Build

Build it properly in Unity or Three.js, with the end card and install button wired in from day one.

04

Optimize

Compress assets, cut dead code, profile until it fits every network's size and load-time limit.

05

Ship

Export per-network builds, test on real low-end phones, hand it over with notes on how it performs.
